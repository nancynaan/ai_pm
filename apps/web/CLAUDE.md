# Web UI

Loaded when working in `apps/web`. React 19 + Vite; served by the server from `apps/web/dist` in Docker.

- **Routes** (hash routing in `App.tsx`): `#/` the home page (new request + recent requests; the header shows only a System status button), `#/status` system status (health checks, the project baseline, and the Run log in `RunLog.tsx`: one collapsible row per feature with its steps, time, Claude calls, tokens and repairs from `GET /api/runs/:id/log`; a step seen before is marked "re-run", or "retry" after a failure). A feature screen has the tabs Chat `#/runs/<id>`, Analysis `#/runs/<id>/analysis`, Documents `#/runs/<id>/documents` (previews `…/documents/<type>`) and Presentation `#/runs/<id>/presentation` (slide viewer `…/presentation/slides`) in the header, plus Backlog `#/runs/<id>/backlog` only once an approved feature's backlog is in Jira (`useHasBacklog` in `Backlog.tsx`, rechecked on the `aipm:backlog-changed` window event the chat sends), and "AI PM" top left goes home. Old `#/analysis/<id>` links open the Analysis tab; `#/analysis` (all assessments) has no tab.
- **Chat vs Analysis:** the chat shows the conversation, the questionnaire, the discovery report and decision cards. Phase 4 numbers live only on the Analysis tab (`Analysis.tsx`); the chat gets an `assessment_ready` card that links there. Keep later phases' figures on the Analysis tab too. The Documents card (`Documents.tsx`) sits below the client's "Generate the documents" (or "Skip the documents for now") message (event key `documents.request`), or below the latest assessment card before that request exists. It has a table (Document, Status, Preview, Confluence), right-aligned buttons, each shown only while its step is to do (no re-generation, no re-publish): "Generate documents" (green `button.go`) and "Publish to Confluence" (`PublishButton`: grey `go locked` with a hint until it can be used, then green; a 10 px note under it, "Required to approve"), then "Skip for now" (green `--ok-text` link, any verdict, at the documents step). The card follows the latest request (`documents.request` or `documents.request.late`, a late generate at the decision). The decision card locks Approve (`go locked`, aria-disabled, hint "Publish the documents to proceed.") while the documents are not published; a click still goes to the API, which answers in the chat. while the documents are generated the card shows a "please wait" line instead of the table. It reloads on `state` and `documents` events. The Proposal card has View slides and Download PPTX (white `a.button.light`) and the same `PublishButton` with "Optional", right-aligned; the publish button is enabled only after the documents are published and disappears once the deck is published (then the Confluence link shows). **Waiting:** while a step works, the chat ends with a `StepWaitingCard` (`Waiting.tsx`: title, "In progress" or "Paused", a "please wait" line with three dots that respect reduced motion) where that step's result will appear; it disappears when the state changes. Previews render Markdown through `Markdown.tsx` (React elements from marked tokens, never raw HTML). The client deck (`Presentation.tsx`) has its own fixed palette (`.slide` tokens, the same in light and dark, sized with container units so it scales to phone width); the chat gets a Proposal card, and only the latest decision card is active. The decision card has two buttons, Decline and Approve. After the decision the conversation is closed: Declined shows a red Backlog step (`.timeline .stopped`) and a red closing banner; Approved (state `completed`) shows every step green, the Backlog card (`BacklogCard`: Epic link, stories with keys, proposed priority, AI estimate) under the `backlog_ready` event, and the same card on the Backlog tab.
- **Data:** fetch through `api.ts` and validate every response with the zod schemas from `@ai-pm/shared`. Live updates come from the run's SSE stream (`RunView.tsx`).
- **Chat text** (`RichText.tsx`) supports paragraphs, `- ` lists, `**bold**` and absolute `https://` links only; use an event and a card for in-app links.
- **Charts** (`charts.tsx`): plain SVG, no chart library. Colors only from CSS tokens in `styles.css` (`--series-1..3`, validated as a set for light and dark; `--status-*` for risk levels with a text label). Thin marks, 4px rounded bar tops, 2px lines, a hover tooltip on every chart, a legend for two or more series, and a table next to each chart.
- Styles: one `styles.css` with light and dark tokens. Theme: the page is blush `--page-base` with soft blue ripples (a repeating radial gradient over a repeating linear one, `--page-ripple-from` → `--page-ripple-to`, the same in both modes); cards, bubbles and buttons are warm surfaces with light neumorphism (`--raise`, `--raise-sm`, `--press`, `--edge`); fields sit in inset wells. Text that would sit on the gradient (header, status lines, back links, feature title) gets a frosted `--surface-glass` backing. Client bubbles are steel navy (`--client-bg`/`--client-text`). Page frame: `#root` (max-width 960 px, 1120 px with `.wide` set by `App.tsx`; padding-top 20 px) holds `.topbar` and `<main>`. `.topbar` is sticky at `top: 0` and holds two siblings: the bar `header.top` (dark slate `--nav-glass` #1e2929 with a backdrop blur, 8 px corners; "AI PM" top left is boxed with a 2 px `--nav-text` border) and `.topbar-fade` (a short masked blur strip under it). Keep them siblings: a backdrop filter nested inside another only sees its parent. `scroll-padding-top` keeps anchored jumps below the bar. The bar is the darkest surface in both modes (`--nav-*`; the current tab in light blue `--nav-active`). Go-ahead actions (Generate, Publish, Approve, and the links Open the Analysis tab and Open the Epic in Jira as `a.button.go`) use green `--go-bg`; links in the AI's chat messages are `--ok-text` green, Decline uses `button.stop` (red). Keep text at ≥ 4.5:1, also on glass over the dark end of the gradient; layouts must work at phone width without horizontal scroll. A table that is too wide for a phone goes in `<div className="table-wide">`: below 640 px it scrolls sideways inside the card with the first column pinned (sticky, card background, hairline divider) and a soft shade on the right edge while more is hidden; on desktop the wrapper does nothing. Prose cells in it wrap at 200–240 px; headings, `.num` cells and the pinned column stay on one line. A control that is locked for good (e.g. Publish after the decision) uses `aria-disabled="true"` instead of `disabled`, so it stays focusable, and sits in `.hint-wrap` with a `.hint` tooltip (role tooltip, `aria-describedby`) that shows on hover, keyboard focus and tap; the reason comes from the API (`lockedReason` on the documents set and on the presentation).
