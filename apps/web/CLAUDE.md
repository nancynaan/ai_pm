# Web UI

Loaded when working in `apps/web`. React 19 + Vite; served by the server from `apps/web/dist` in Docker.

- **Routes** (hash routing in `App.tsx`): `#/` the home page (new request + recent requests; the header shows only a System status button), `#/status` system status. A feature screen has the tabs Chat `#/runs/<id>`, Analysis `#/runs/<id>/analysis`, Documents `#/runs/<id>/documents` (previews `…/documents/<type>`) and Presentation `#/runs/<id>/presentation` (slide viewer `…/presentation/slides`) in the header, and "AI PM" top left goes home. Old `#/analysis/<id>` links open the Analysis tab; `#/analysis` (all assessments) has no tab.
- **Chat vs Analysis:** the chat shows the conversation, the questionnaire, the discovery report and decision cards. Phase 4 numbers live only on the Analysis tab (`Analysis.tsx`); the chat gets an `assessment_ready` card that links there. Keep later phases' figures on the Analysis tab too. The Documents card (`Documents.tsx`) sits below the client's "Generate the documents" message (event key `documents.request`), or below the latest assessment card before that request exists: the publish button and a table of documents with Confluence links and previews; it reloads on `state` and `documents` events. Previews render Markdown through `Markdown.tsx` (React elements from marked tokens, never raw HTML). The client deck (`Presentation.tsx`) has its own fixed palette (`.slide` tokens, the same in light and dark, sized with container units so it scales to phone width); the chat gets a Proposal card, and only the latest decision card is active.
- **Data:** fetch through `api.ts` and validate every response with the zod schemas from `@ai-pm/shared`. Live updates come from the run's SSE stream (`RunView.tsx`).
- **Chat text** (`RichText.tsx`) supports paragraphs, `- ` lists, `**bold**` and absolute `https://` links only; use an event and a card for in-app links.
- **Charts** (`charts.tsx`): plain SVG, no chart library. Colors only from CSS tokens in `styles.css` (`--series-1..3`, validated as a set for light and dark; `--status-*` for risk levels with a text label). Thin marks, 4px rounded bar tops, 2px lines, a hover tooltip on every chart, a legend for two or more series, and a table next to each chart.
- Styles: one `styles.css` with light and dark tokens. Theme: the page is a sand-to-slate gradient (`--page-from` → `--page-to`, the same in both modes); cards, bubbles and buttons are warm surfaces with light neumorphism (`--raise`, `--raise-sm`, `--press`, `--edge`); fields sit in inset wells. Text that would sit on the gradient (header, status lines, back links, feature title) gets a frosted `--surface-glass` backing. Client bubbles are steel navy (`--client-bg`/`--client-text`). Page frame: `#root` (max-width 960 px, 1120 px with `.wide` set by `App.tsx`; padding-top 20 px) holds `.topbar` and `<main>`. `.topbar` is sticky at `top: 0` and holds two siblings: the bar `header.top` (dark chocolate `--nav-glass` at 90 % with a backdrop blur, 8 px corners, so content passing under it is softly blurred) and `.topbar-fade` (a short masked blur strip under it). Keep them siblings: a backdrop filter nested inside another only sees its parent. `scroll-padding-top` keeps anchored jumps below the bar. The bar is the darkest surface in both modes (`--nav-*`; the current tab in light blue `--nav-active`). Go-ahead actions (Publish, Approve) use `button.go` (green), Decline uses `button.stop` (red). Keep text at ≥ 4.5:1, also on glass over the dark end of the gradient; layouts must work at phone width without horizontal scroll.
